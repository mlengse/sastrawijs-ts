## Performance Optimizations

- **Suffix Removal**: Replaced regular expression `string.match(...)` in `removeParticle`, `removePossessive`, and `removeSuffix` with direct string length inspection and `endsWith(...)` checks. This eliminated regex matching overhead and match array allocations, yielding a ~2.4x–2.6x speedup (~60% time reduction) compared to regex matching and ~6.5x speedup (~85% time reduction) compared to double string replacement.
- **Last Return Loop Optimization**: Replaced `suffixes.forEach` callback loop with a standard `for` loop in `Stemmer.lastReturnLoop` to avoid callback execution overhead when summing suffix lengths, yielding a ~5% speedup in microbenchmarks.

## Combining Regex Replace Operations for String Parsing

When parsing or decoding encoded characters in strings (such as numeric HTML entities `&#x...;` vs `&#...;`), combining two separate `.replace()` regex scans into a single regex with alternative capture groups (e.g., `/&#(?:x([0-9a-fA-F]{1,6})|([0-9]{1,7}));/g`) eliminates an entire second pass over the string. This reduces string scanning overhead and function call allocations, yielding measurable performance gains (~3%+ throughput improvement) while preserving exact behavior.

- **Regex Constant Extraction**: Extracted the repeated inline regular expression `/^(be.+lah|be.+an|me.+i|di.+i|pe.+i|ter.+i)$/` in `Stemmer.stem` to a top-level module constant `PREFIX_FIRST_REGEX`. This avoids re-instantiating and compiling the regex object on every `stem()` call, yielding an ~11% speedup (~1.13x) in regex test execution.

- **Tokenizer Regex Constant Extraction**: Extracted inline regular expression literals in `Tokenizer` (`HTML_ENTITY_REGEX`, `HTML_TAG_REGEX`, `URL_REGEX`, `EMAIL_REGEX`, `MENTION_HASHTAG_REGEX`, `NBSP_REGEX`, `NAMED_ENTITY_REGEX`, `NON_ALPHA_SPACE_REGEX`, `WHITESPACE_REGEX`) to top-level module constants. This eliminates redundant regex instantiation and compilation on repeated calls to `parseHtmlEntities` and `tokenize`, improving code clarity and avoiding unnecessary object allocations per execution pass.

- **Tokenizer Regex Consolidation**: Consolidated 7 sequential `.replace()` calls in `Tokenizer.tokenize()` into two unified regex replacement passes (`STRIP_REGEX` for URLs, emails, mentions/hashtags, named entities; and `CLEAN_REGEX` for HTML tags, `&nbsp;`, non-alphabetic characters). This eliminates intermediate string allocations and reduces scan overhead, yielding a ~1.15x speedup (~12.9% reduction in runtime).

- **Tokenizer Redundant Whitespace Pass Elimination**: Removed the redundant `.replace(WHITESPACE_REGEX, " ")` pass prior to `.trim()` and `.split(WHITESPACE_REGEX)`. Since `String.prototype.split(/\s+/)` natively handles consecutive whitespace sequences, skipping the intermediate full-string regex replacement pass avoids unnecessary string scans and allocations, yielding a ~1.5x throughput improvement (~35% reduction in runtime).

- **Hyphenated Suffix Removal Optimization**: Replaced redundant `word.slice(len - 4)` substring extractions for hyphenated suffixes in `removeParticle`, `removePossessive`, and `removeSuffix` with static string literals containing leading hyphens (e.g. `"-lah"`, `"-ku"`, `"-kan"`). Because the suffix text is already matched by `endsWith()`, returning `"-" + particle` or `"-ku"` avoids redundant substring allocation from slicing the end of the input word.

- **Cumulative Suffix Combination in `lastReturnLoop`**: Replaced `suffixes.slice(0, i + 1).join("")` array allocations in each iteration of `Stemmer.lastReturnLoop` with direct string accumulation (`suffixCombination += suffixes[i]`). This avoids allocating intermediate subarray copies and joining array elements on every iteration, yielding an ~11x speedup in isolated loop benchmarks (~91% runtime reduction) and a ~15% throughput gain (~675k to ~778k ops/sec) in `lastReturnLoop`-heavy workloads.

- **Single-Pass Tokenizer Cleaning Regex**: Consolidated `STRIP_REGEX` (URLs, emails, mentions, hashtags, named entities) and `CLEAN_REGEX` (HTML tags, `&nbsp;`, non-alphabetic characters) in `Tokenizer.tokenize()` into a single `TOKEN_CLEAN_REGEX` pass (`.replace(TOKEN_CLEAN_REGEX, " ")`). Combining these chained `.replace()` operations into a unified single-pass regex replacement eliminates intermediate string allocations and string scans, yielding a ~1.08x speedup (~7.7% reduction in runtime, increasing throughput from ~359k to ~389k sentences/sec).
